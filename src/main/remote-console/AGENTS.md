# Remote Console (main process)

The phone Remote Console (#254): watch and answer agent panes from a phone browser. **Off by default, loopback by default.** `index.ts` is the FACADE and the only module the rest of main imports: it loads `./runtime` with a bare lazy `require` (the `cli-paths.ts` idiom) so the server/ws/crypto work stays off startup and main compiles whether or not the runtime is present — which also makes a packaging miss SILENT (`remote-console-missing` in main.log, `null` everywhere), hence release.yml's check for it in the packaged asar. `contract.ts`'s `ConsoleOps` is the COMPLETE list of what the console can do to the app, built in main's `index.ts`; `taps.ts` holds the no-op hooks both PTY forwarders call (always through the object, never destructured).

Seven invariants, each a reason something is shaped the way it is: **I1** separate dispatcher — the console never touches the pipe token or the V2 switch, its message table is deny-by-default and reaches only `ConsoleOps`; **I2** no credential mint over the pipe — the pipe gets exactly one read-only method, `remote.status` (NOT in `PUBLIC_V2_METHODS`), and pairing/enable/revoke are Settings clicks, because anything a pipe command can do a prompt-injected agent holding the token can do; **I3** off and loopback by default, a LAN bind is viewer-only unless `allowInsecureControl` is acknowledged twice; **I4** remote input obeys every back-channel rule — answers only through `deliverAnswer` (the `pane.answer_agent` path: blocked-only, declared payload, never clears blocked), `noteHumanInput` immediately before each write with the identical bytes, blocked snapshotted before any write, the phone never resizes a PTY, never an implicit surface; **I5** the pairing secret rides in the URL FRAGMENT and is stripped by the page's first statement; **I6** persistence (`remote-console.json`, `remote-devices.json` with token HASHES only) stays under `getAppDataDir()`, so the #132 consent gate is not engaged; **I7** no existing boundary moves, and command lines, `report_command`, session ids, cwd, notification text and choice `key`/`text` never go on the wire — main.log records byte counts, never typed content.

`will-quit` is synchronous, so teardown is `stopNow()` (timers, sockets, `server.close()`, taps reset — no await), called right after the `will-quit` log line and before the PTY drain. The taps are installed only while the server listens, and a forwarder binds once, at PTY creation — so `ipc-handlers.ts` keeps its OWN surfaceId → webContents map and `replayRemoteBindings()` re-announces it on every not-running → running edge, after `start()` and after `setConfig`; without it every pane open before the user flipped the switch answers `no-terminal` on the phone
